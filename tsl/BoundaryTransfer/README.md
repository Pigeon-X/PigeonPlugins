# BoundaryTransfer 1.2.0：UTSL 左右边界直达 + 海边保护

版本 **1.2.0**；目标为 **UnifierTSL 0.3.1-tshock6.1-cn / Terraria 1.4.5.8 / .NET 9**。

独立的 UTSL 原生插件，不修改 UTSL 核心，不修改世界出生点。

## 1. 本次改动

- **保持接触高度**：玩家在什么脚底 Y 碰到边界，就出现在对侧边界相同脚底 Y。
- **贴对侧原生边界**：使用 Terraria 实际可达的 `640px`（40格）边界线，而不是旧版的 96 格内缩。
- **海边保护（1.2.0）**：目标同高度点在海里、无地面或被墙体挡住时，沿对侧边界向内找**地表海岸**；只在 `worldSurface` 附近、`rockLayer` 以上搜索，绝不选地下水洞或地狱。正常陆地/地底仍保持同高度直达。
- **无混沌传送杖特效**：不再使用 TShock `Teleport(..., style=1)`。改用 Terraria `Teleport` 的 **style 6**；该样式在 `Main.TeleportEffect` 和 `Player.UpdateTeleportVisuals` 中都没有粒子/音效分支，视觉上等同原生切图。
- 旧配置里的搜索项不再生成、不再生效；旧 JSON 仍可加载，不会报错。新增 `海边保护`、`海岸水平搜索_格`、`海岸上下搜索_格`。

行为示例：

```text
左侧世界  ←→  中间世界  ←→  右侧世界
```

- 玩家在中间世界左边界脚底第 300 格接触边界 → 进入左侧世界右边界，脚底仍是第 300 格附近。
- 玩家在中间世界右边界脚底第 800 格接触边界 → 进入右侧世界左边界，脚底仍是第 800 格附近。
- 正常陆地只按当前脚底高度映射；如果对侧同高度是海水/无地面/墙体，才沿海岸线向内找地表干燥海岸，不会下地下水洞或地狱。

## 2. 安装与配置

1. 将 `plugins/BoundaryTransfer.dll` 放进 **UTSL 原生 `plugins` 目录**，不要放进只扫描传统 TShock 插件的目录。
2. 重启 UTSL 或通过原生插件加载机制加载。首次生成：

```text
config/BoundaryTransfer/BoundaryTransfer.json
```

3. 管理员或控制台设置世界排列：

```text
/边界 世界
/边界 排列 左侧世界 中间世界 右侧世界
/边界 列表
```

世界名必须与 `/边界 世界` 输出的 `ServerContext.Name` 完全一致；不是磁盘文件名或序号。含空格用英文双引号。

默认排列为空，安装后不会自动连接现有世界。必须满足：

- 相邻世界在同一 UTSL 进程内运行。
- 地图宽度、高度一致（核心原生无缝入口限制）。
- 目标世界允许加入，其他插件可以取消原生切服。
- 正常重力、活着的正常玩家才触发。

配置默认值：

```json
{
  "启用": true,
  "从左到右的世界名": [],
  "首尾循环": false,
  "碰边容差_像素": 2,
  "海边保护": true,
  "海岸水平搜索_格": 400,
  "海岸上下搜索_格": 40,
  "位置检测间隔_毫秒": 50,
  "切换冷却_毫秒": 3000,
  "切换超时_毫秒": 20000,
  "落点确认保护_毫秒": 2500
}
```

- **碰边容差 2 像素**：按人物碰撞框左右身体面判定。Terraria 原生可走边界是 `leftWorld + 640px` / `rightWorld - 640px`；右侧扣当前人物宽度。
- **海边保护**：开启后，同高度点若在水里/无地面/墙体，会沿对侧边界向内搜索地表海岸；水平默认最多 400 格，上下只在 `worldSurface ±40` 格内，且不超过 `rockLayer`。找不到干燥海岸则本次不切换，不会硬塞水里或钻地底。
- **位置检测间隔 50 毫秒**：只控制源世界检查频率，不保证网络零帧切换。
- **切换冷却 3000 毫秒**：完成后必须让完整身体退到边界内侧 8 格以外，再回边界，防止两图来回弹。
- **落点确认保护 2500 毫秒**：短窗口内拦住仍带旧地图坐标的移动包；客户端报告落点 16 格内坐标即放行。高延迟可调到 `5000`。

旧版 `进入对侧内缩_格`、`向地图内部搜索_格`、`上下安全搜索_格`、`危险物缓冲_格`、`单次搜索候选上限` 已被忽略；即使旧 JSON 里保留也不会改变落点。旧 `触发边界距离_格`、`显示切换提示` 同样忽略。

## 3. 命令与权限

管理权限：`boundarytransfer.admin`。普通玩家自动使用已配置的边界，无需权限。

管理入口隐藏，不进入公共 `/help` 和指令目录；执行回执只回复本人，不广播“某人执行了指令”。

| 命令 | 作用 |
| --- | --- |
| `/边界 世界` | 查看世界名、运行状态、地图尺寸 |
| `/边界 排列 <最左> <中间> ...` | 保存从左到右排列，至少两个、不允许重复 |
| `/边界 列表` | 查看启用、排列、首尾循环 |
| `/边界 重载` | 重新读取配置 |
| `/边界 帮助` | 查看本人帮助 |

英文别名：`/boundarytransfer`、`/borders`；子命令 `worlds`、`order`、`list`、`reload`。

## 4. 无特效实现

正式落点不调用 TShock 的 `TSPlayer.Teleport(x, y, 1)`，而是：

1. 设置玩家原生位置、清零速度、清理抓钩/滑轮。
2. 给客户端发目标区块 `SendTileSquareCentered` 和 `CheckSection`。
3. 调用原生 `Player.Teleport(server, position, 6, 0)`。
4. 手工发送 `65` 号 `PlayerTeleport` 包，style 固定为 `6`。

依据当前基线反编译：

- `Main.TeleportEffect` 只处理 style `0/1/2/3/4/5/7/9/10/11/13`；**没有 6**，不会产生传送粒子或音效。
- `Player.UpdateTeleportVisuals` 只对 style `0/1/2/3/4/9` 做逐帧效果；**没有 6**，不会出现混沌传送杖的粉色/白色粒子。
- 因此 style 6 是“位置同步但不播放传送特效”的样式。

客户端仍需要接收目标地图区块，不能承诺完全没有加载时间；这里只保证不播放混沌传送杖/普通传送粒子。

## 5. 不改出生点与核心边界

插件没有写入 `Main.spawnTileX/SpawnTileY`，没有把 `Player.SpawnX/SpawnY` 改成边界坐标，也没有用床或出生点替代位置传送。

跨世界只调用：

```csharp
UnifiedServerCoordinator.TransferPlayerToServer(slot, target);
```

原生入口没有坐标参数；流程为：边界判定 → 原生切图 → 目标 Spawn 握手后无特效位置同步。核心自身跨世界时仍会清空 `SpawnX/SpawnY` 并执行原生 Spawn 初始化，这不是本插件修改落点的手段。

## 6. 失败与直落风险

- 目标未运行、尺寸不同、进入条件失败、原生切服被取消、超时：保留原世界，不发玩家聊天提示，只写服务端节流日志。
- 直达落点不检查地形，可能落在水里、空中或实心方块内。这是按“直接切换、不考虑安全落点”的要求；插件不会再把你搬到远处安全地面。
- 客户端落点 16 格内报告坐标即认为到达；边界地形把人物轻微挤出仍可继续。
- 超时未确认只关闭票据捕获的原 Socket，不误伤复用槽位的新玩家。
- 卸载：停止新增切换，最多异步等待 6 秒；残留未完成票据只关闭捕获的原连接。

## 7. 编译与验证

```powershell
dotnet build BoundaryTransfer.UnifierTSL.csproj -c Release -p:UtBase="E:\实际UTSL目录"
```

`UtBase` 需包含 `lib/UnifierTSL.dll`、`lib/OTAPI.dll`、`lib/OTAPI.Runtime.dll`、`lib/Newtonsoft.Json.dll` 和 `plugins/TShockAPI.dll`。这些依赖全部 `Private=false`，不重复分发。

本版验证：

- 纯算法/配置/协议测试：**200/200 通过**，包含直达落点高度与边界、旧搜索键忽略、无特效 style 断言。
- 真实 OTAPI 图格/运行时探针：**93/93 通过**，包含直达落点、包钩子、隐藏指令和卸载。
- 官方 DotnetPluginHost 加载探针：**12/12 通过**，包含配置生成、文件监视、热重载和卸载。

**尚未用真实 Terraria 客户端做端到端联机验证。**第一次上服请在测试世界检查：左右双向、跨图后 Y 是否保持、目标边界是海/空/墙时的表现、客户端是否仍有混沌传送粒子、高延迟、死亡复活、其他传送插件取消等。
