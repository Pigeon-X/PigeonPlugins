# BoundaryTransfer 碰边、直达落点、隐藏指令与事件优先级测试

- `net9.0` console，程序集名 `BoundaryTransfer.Tests`，直接 `ProjectReference` 主项目；通过主项目既有的 `InternalsVisibleTo` 调用真实内部算法，不复制 Planner 源码。
- 无 xUnit/NUnit/MSTest 或其他第三方 NuGet 测试框架。只引用指定 UTSL 0.3.1 基线现有 DLL；构建时把 `lib` 原样复制到测试输出目录，另带 `TShockAPI.dll`。
- 所有测试代码和日志均位于本目录。运行不会启动服务器、客户端、监听网络或初始化 Terraria 元数据。

## 运行

在本目录执行：

```powershell
dotnet build .\BoundaryTransfer.Tests.csproj -c Release --nologo
dotnet .\bin\Release\net9.0\BoundaryTransfer.Tests.dll --log .\result.log
$LASTEXITCODE
```

默认基线目录由测试项目计算为 `E:\流光核心源码\_参考资料\官方源码\UnifierTSL更新\已完成\0.3.1-tshock6.1-cn\utsl-win-x64`。也可传 `-p:UtBase=<同结构基线根目录>` 覆盖。

## 结果格式

`result.log` 是 UTF-8 JSON Lines：

- `type=suite`：运行范围、确定性种子与客户端/元数据未验证声明。
- `type=case`：稳定测试 ID、类别、`passed` / `failed`、断言数，失败时含异常和堆栈。
- `type=summary`：`total`、`passed`、`failed`、`skipped`、`assertions`、`exitCode`。

退出码：`0` 全通过，`1` 至少一个用例失败，`2` 参数错误或宿主/日志基础设施失败。配套 `exitcode.txt` 保存最近一次执行的实际进程退出码；`console.log` 为可读控制台输出，`build.log` 为编译输出。

## 覆盖与边界

1.2.0 共 **204 个独立 case、28193 条断言，全部通过**，实际退出码 0。新增海边保护 case：海水对侧向内地表海岸、绝不选地下/地狱、全海无解不切换。此前直达落点 case 仍保留：左右两侧保持接触脚底 Y、贴对侧 640 像素原生边界、空地图也不拒绝、只在超出原生上下范围时夹取、旧搜索配置项不再序列化、无特效 style 6 断言。历史安全搜索测试保留，仅回归旧算法，不代表 1.2.0 正式路径。

1.0.3 的 30 项兜底 case 仍可运行，但正式插件不再调用：海岸超出旧内部搜索范围、海底和实心地层下的干燥洞穴、高空已有地面、全空/全液无解、安全缓冲仍强制、边界距离优先和列内原Y距离优先、完整身体宽高、严格候选预算与分帧续搜、计时让帧、终态不再读图、验证回调拒绝后继续、尺寸变化、配置不变与不可写地图。

1.0.2新增32个碰边与方向 case：身体左右面对齐640像素原生边界、动态宽度、容差、非零世界起点、极端/非有限坐标、完整身体退出8格再武装、固定随机种子的左右对称性质，以及朝外按键/惯性、顶边速度归零、反向和双键阻止切换。新增配置兼容测试验证旧 `触发边界距离_格` 与 `显示切换提示` 被忽略。

原有安全搜索、路由和配置覆盖继续保留：左右相邻世界、端点/循环、完整人体碰撞框、完整脚掌承重、平台/半砖/斜坡/未知/装饰/未激活地图抽象、液体与危险缓冲、同 Y 优先、上下偏移顺序、地狱和不同世界高度、搜索半幅/范围/预算、坐标有效性、不可写地图、配置范围/重复世界名、设置与两种 JSON 的交叉 roundtrip。旧按中心提前触发的4项已由新的身体接触规则替代。

1.0.1 新增 22 个隐藏指令解析 case：三个别名、英文大小写、精确根命令、自定义/静默前缀、控制台无前缀、普通聊天放行、含空格世界名、转义及未闭合引号拒绝。另有 2 个真实发行事件优先级 case：验证干净基线中私密入口先于核心入口，以及 `Highest-1` 会转为 byte 的 255 而排到最后。该组结果保存于 `hidden-result.log`，不应把两项真实事件测试称为纯地图算法。

地图构造后使用 `FrozenDictionary` 不可写；`Get` 越界直接抛错，可及时发现算法边界缺陷。搜索顺序用声明式候选枚举排序作独立 oracle。固定随机种子为 `314159`，没有时间、线程、真实客户端或网络依赖。

水、岩浆、蜂蜜、微光在本测试中都故意抽象为相同的 `TileCell.Liquid` 标志；半砖/斜坡等也只是 `TileCell` 契约样本。这验证 Planner 对这些标志的处理，**不验证真实 Terraria tile metadata 的转换、服务端生命周期、客户端落地同步或原生切服网络行为**。未调用 Initializer，因此也不存在未设置 LauncherSurfaceConsole 的隐式元数据初始化。
